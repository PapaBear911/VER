# Gate: Spec Before Edit

**Phase:** Phase 1 — VISUALIZE (Hard Gate 1)  
**Invariant:** Visualize always precedes Engineer.

---

## The Rule

An agent must never modify source code, configurations, schemas, dependencies, or real-world operational procedures before the Vision, its contract, and required authorities are explicitly approved.

## Falsifiable Checks

1. **Explicit Session Approval:** Approval token (`yes`, `go`, `approved`, `ship it`, `looks good`) received in session for the presented V.E.R. scope.
2. **Institutional Authorization Boundary:** For consequential interventions (policy enactments, clinical/research trials, physical installations), identify the authorized bodies/persons and reference the record establishing their authority before activity begins.
3. **Defined Blast Radius:** The files, procedures, and systems intended for editing are named in the Vision. Unnamed targets must not be touched.
4. **Observable Success Criteria:** Observable pass and fail criteria defined upfront.
5. **No Speculative Scaffold:** No scaffolding, hypothetical abstractions, or unrequested procedures that serve no immediate user or operational need.
