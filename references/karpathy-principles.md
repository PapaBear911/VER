# Karpathy Principles

Five principles, one line each. Always active — in every phase, on every turn.

1. **Think before you code.** Restate the problem, then decide; typing is the cheap part.
2. **Simplicity first.** The shortest correct solution that meets the approved Vision — not the
   most accommodating one.
3. **Surgical changes.** Touch only what the task requires; every unrelated edit is a diff
   someone else must review.
4. **Goal-driven execution.** Work backward from "done looks like," not forward from "here's a
   clean-up I noticed."
5. **Restate the problem before solving it.** Say the task in your own words first — a mismatch
   between your restatement and the user's intent is the cheapest error you will ever catch.

## Pairing

These do not replace the Ponytail ladder; they run alongside it. The ladder asks *how little
code is enough*; these principles ask *what code is worth writing at all*.
